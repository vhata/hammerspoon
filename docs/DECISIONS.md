# Decisions

Non-obvious choices and their trade-offs, dated, newest section first. Read the relevant entry before changing a mechanism that looks odd. Choices made autonomously under a delegation are recorded here for the user to review; an entry is a record, not a claim that the capability is complete.

## 2026-10-17

| Decision | Reason and trade-off |
| --- | --- |
| Global hotkeys are bound through `hotkeys.bind` (`hotkeys.lua`), which records a hotkey only when `hs.hotkey.bind` returned one, and the leader's `?` overlay lists those of the recorded hotkeys that `hs.hotkey.getHotkeys()` returns when it opens. | The help is built from the same calls that bind the keys, as the leader tree already was, so a key that failed to bind (unknown on the layout, refused by macOS) never appears, and `getHotkeys()`, which returns the one hotkey answering each combination, drops one that was later disabled or shadowed by another binding of the same keys. The labels live in the registry rather than in `getHotkeys()`'s descriptions because those come from the hotkey's alert message, and a hotkey with a message flashes it as an alert on every press unless `hs.hotkey.alertDuration` is set to 0 for everything. Cost: a module that calls `hs.hotkey.bind` directly still works but is missing from the help; keys that are live only while something is open (the calendar's arrows, Escape on overlays, the vendored AClock's Escape) are not listed. |
| Hyper+K and Hyper+B make the note in Hammerspoon, opening the same `obsidian://new` URL that `~/bin/intake` builds, rather than running the Intake shortcut or `~/bin/intake`. | The shortcut always writes to the Personal vault and its Ask for Input dialog opens through Shortcuts; `~/bin/intake` takes no vault, and changing it is outside this repository. A chooser opens at once, takes the keyboard, and Escape cancels. Cost: the note naming and encoding (`Intake/YYYY-MM-DD HHMMSS`, jq `@uri` percent-encoding) exist in two places, so a change to `~/bin/intake` is not picked up here. |
| The capture prompt is an `hs.chooser` with one row that mirrors the typed text, not `hs.dialog.textPrompt`. | `textPrompt` runs a modal dialog that blocks Hammerspoon's main thread, and every hotkey and the leader tap with it, until it is answered. The chooser is non-blocking. Cost: input is one line, as the shortcut's Ask for Input also is; Return on an empty prompt makes an empty note, as `~/bin/intake` does with no input. |

## 2026-10-12

| Decision | Reason and trade-off |
| --- | --- |
| The now-playing notification waits at most three seconds (`ARTWORK_TIMEOUT` in `spotify.lua`) for album art, then is sent without it; art that arrives later is dropped rather than replacing or resending the notification. | Since the fetch became asynchronous the notification waited for it, which on a slow or dead link could be as long as the system URL timeout. One notification per press keeps a slow link from producing a second one after the first has been read. Cost: on a link slower than the timeout the notification never has art, even when the image would have arrived a moment later. |
| luacheck is its own gate, `scripts/luacheck.sh`, run by the pre-commit hook after lint, by `scripts/check.sh` and by the CI `check` job. | A separate script keeps `scripts/lint.sh` a pure syntax check. Running it in the hook, added at the user's request, catches a new accidental global or unused local at commit time rather than in CI; it adds well under a second. Cost: committing requires luacheck to be installed (`brew install luacheck`); without it the hook fails with an install hint. |
| CI installs luacheck from Ubuntu's `lua-check` package rather than through luarocks. | It is one more name on the existing `apt-get install` line, with no compiler or rocks tree. Cost: Ubuntu 24.04 ships 1.1.2 while Homebrew ships 1.2.0, so a warning added in a later release can appear locally first. |
| The vendored `AClock` and `Emojis` spoons are excluded from luacheck. First-party code has no baseline of tolerated warnings; each deliberate one is ignored where it occurs, with the reason. | They are upstream code (AClock sets the global `getframe`; Emojis adds `table.save` and `table.load` to the shared `table` library), and fixing their warnings means a local patch to reapply on every update. First-party code had two warnings, both deliberate: the global `reloadFallbackWatcher` in `init.lua` (declared in `.luacheckrc`) and `reload.lua`'s held-but-never-read `watcher` (inline ignore); both exist so the garbage collector cannot stop a watcher. Cost: new warnings in either spoon, including after an upstream update, go unseen. |

## 2026-10-09

| Decision | Reason and trade-off |
| --- | --- |
| The config reloads through `reload.lua`; the vendored `ReloadConfiguration` spoon is no longer loaded. | The spoon calls `hs.reload` on the first file event of any kind, so every git operation reloaded and a `git pull` could be loaded half-applied, and its `start()` sat at the end of `init.lua`, so a load that failed earlier left nothing watching. Changing that means editing upstream code. The spoon's reload hotkey was never bound, so nothing else is lost. Cost: the spoon directory stayed in the tree unused until it was deleted on 2026-10-10. |
| A reload waits for one second without a matching change (`hs.timer.delayed`, restarted on every event). | A pull writes its files in a burst, so the reload sees the finished tree instead of the first file. Cost: every edit takes a second to apply. A checkout that pauses for longer than that mid-write can still be loaded half-applied; because the watcher starts first, its remaining writes then reload again. |
| Only `.lua` and `.json` files count, and nothing under a hidden directory or inside a directory holding a `.git` entry. | `require` and `hs.loadSpoon` load `.lua`; spoons read their `docs.json` while loading, and Emojis reads `emojis.json` when its generated Lua cache is missing. Other assets (`marked.min.js`, the emoji PNGs) are read when used and need no reload. Hidden directories cover `.git/`, `.worktrees/`, `.docket/` and editor swap files; the `.git` test covers a worktree or clone under any name. Cost: a new kind of file read at load time must be added to `EXTENSIONS` in `reload.lua`, removing a nested worktree with a non-hidden name may reload once, because its `.git` can be deleted before the rest of its files; moving a whole directory in or out (dragging a spoon into `Spoons/`) reports only the directory and does not reload; and a spoon that is itself a git clone (`Spoons/X.spoon/.git`) would never reload on its edits. |
| `init.lua` starts the watcher before anything else, inside a `pcall`, and falls back to an unfiltered watcher in the global `reloadFallbackWatcher` if `reload.lua` fails. | A typo in `reload.lua`, or a pull that renames it, would otherwise leave no watcher at all. The fallback reloads on any change, as `ReloadConfiguration` did, until `reload.lua` loads again. The global is deliberate: a `local` in `init.lua` would be garbage-collected, stopping the watcher, once the file finishes running. |
| The open FloatCalendar takes its keys through an `hs.eventtap` that closes the calendar on any other key, modified key or mouse click, instead of through hotkeys bound for as long as it is shown. | Bound hotkeys, or an `hs.hotkey.modal`, are global while active, so `r` and the arrows were taken from every app. An `hs.canvas` cannot take keyboard focus; making the calendar focusable means rebuilding it as an `hs.webview`. Modifier-only presses, scrolling and mouse movement leave it open. Cost: any other key press or click closes the calendar, including a click on it; and while secure input is on (a password field, a terminal's Secure Keyboard Entry) event taps see no keys, so the calendar's keys do nothing and typing does not close it, where the old hotkeys kept working. A click still closes it; the leader's double-tap is also an event tap, so it probably cannot open the leader under secure input either. |
| A `toggleShow` within 1.2 seconds of the calendar closing on another key leaves it closed. | The leader's `o` then `l` would otherwise close the calendar on `o` and reopen it on `l`. The leader's per-layer timeout is one second, restarted just after the calendar records the dismissal, so the grace has a small margin over it. Cost: deliberately reopening it within 1.2 seconds of dismissing it with some other key needs a second toggle. |
| The open calendar checks the date once a minute rather than setting a timer for midnight. | A minute check also covers a Mac asleep through midnight and clock or time-zone changes. Cost: the highlight can lag midnight by up to a minute. |
| The vendored Emojis spoon carries a local patch: it no longer refocuses the previous window through `hs.window.filter.defaultCurrentSpace`. | That filter is Spaces-aware, so `hs.window.filter` keeps a watcher on every running app and re-queries every app's windows on each Space change, on the main thread, from the moment the spoon loads. Since the leader tap began watching `keyDown`, a stall there delays typing too. `hs.chooser`'s default global callback already saves the frontmost window when a chooser opens and refocuses it in `hide`, before the completion callback runs, so the spoon's refocus was redundant. Cost: an upstream update of the spoon would bring the filter back; reapply the patch. |

## 2026-10-08

| Decision | Reason and trade-off |
| --- | --- |
| The leader's keys are one table passed to `leader.setup` in `init.lua`, and the `?` overlay is rendered from the items that call actually bound. | The help overlay and the bindings come from the same data, so they cannot drift; an invalid item (unknown or duplicate key, missing label) is skipped with a console message rather than failing the reload, and is left out of the help too. Cost: other modules cannot add leader keys themselves; they export functions and `init.lua` places them in the tree. |
| Each leader group is its own `hs.hotkey.modal`, and each layer gets the full one-second timeout. | Swapping modals keeps every layer's keys independent (`o` can mean Overlays at the top and Obsidian under `a`) and needs no key-sequence parser. Restarting the timeout per layer keeps a three-key sequence from having to fit in one second. The alert now stays up for as long as its layer is live, rather than half a second. |
| `?` and Escape are bound by the leader in every layer, so tree items cannot use Escape. `?` is bound as Shift+`/`, so a plain `/` item is still possible. | One help key that works wherever you are in the tree, without each group having to declare it. |
| The Cmd+Alt+Ctrl app hotkeys and `hyper.lua` were removed when the apps moved under leader `a`. | The point of the leader is to free global shortcuts. Restoring them is a loop over the same app list calling `hs.hotkey.bind({"cmd", "alt", "ctrl"}, key, ...)` with `hs.application.launchOrFocus`. |

## 2026-10-07

| Decision | Reason and trade-off |
| --- | --- |
| Worktrees live in `~/.hammerspoon-worktrees/`, not `.worktrees/` inside the repository. | `ReloadConfiguration` (deleted 2026-10-10) watched `hs.configdir` (`~/.hammerspoon`) recursively and reloaded on any change, so a worktree inside it would reload the live config on every file an agent edits. A sibling directory stops edits from reloading. Git operations in a worktree of the `~/.hammerspoon` clone (commit, fetch, worktree add) still write under `~/.hammerspoon/.git` and still trigger a reload, as commits in the main checkout always have; a reload is harmless, just noisy. Cost: `start-work.sh` needs `--dir ~/.hammerspoon-worktrees`, and because `git check-ignore` cannot test a path outside the repository, each run appends the expanded `~/.hammerspoon-worktrees/` path to `.git/info/exclude` again and prints advice to add it to `.gitignore`. Ignore that advice; the duplicate exclude lines are inert and safe to delete. Since 2026-10-09 the reload watcher ignores `.git/`, hidden directories and nested checkouts, so neither edits in a worktree nor git operations reload the live config wherever the worktree lives; the location rule in AGENTS.md is unchanged. |
| The lint gate is `luac -p` (syntax only), preferring Lua 5.4. | Hammerspoon embeds Lua 5.4, and no Hammerspoon runtime exists outside the app, so parsing is the only check that runs in CI. luacheck would catch accidental globals and unused locals but needs a config and a clean baseline first; queued as `adopt-luacheck`. Added as a separate gate on 2026-10-12; see that entry. |
| Hooks are a tracked `.githooks/` directory wired by `git config core.hooksPath .githooks`. | Two pre-commit checks, each a plain script, do not justify a hook manager. |
| No scheduled validation workflow. | Nothing here is expensive enough to run on a schedule rather than on every push. Add `main-validation.yml` when a codebase review cadence is wanted, so `review-due.sh` has somewhere to run. |
