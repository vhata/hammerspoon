## Summary

There are 23 open findings, all P3: 15 carried from the landed review
and 8 newly recorded here. Six old findings were fixed on main; the
vendored-churn finding is corrected by documentation in this review.
No P0, P1 or P2 issue was confirmed.

The previous P2 expanse chooser claim was too broad. Hammerspoon's
default chooser callback normally retains the chooser through its
focus-restoration table. The remaining risk is opening it without a
frontmost window; it is now P3 and explicitly inspection-only.
The most direct confirmed input defects remain invalid UTF-8 in long
expansion previews and leader activation after mouse input or stray keys.

New findings include off-Space event taps, the calendar's lower date
boundary, initialization failure isolation and local/CI toolchain drift.
The Space behaviour remains a source-derived hypothesis to confirm in
the running app. This review changes documentation and queues only.

## Invariants

1. Module state is local, except the documented fallback watcher global.
   Luacheck covers maintained Lua; vendored globals are not first-party APIs.
2. Long-lived objects need a durable reference. Framework ownership may
   supply one, but only under its actual conditions; expanse still relies
   on there being a frontmost window when the chooser opens.
3. Blocking callbacks stall Hammerspoon's main thread, including hotkeys
   and the leader tap. The artwork download deadline does not bound the
   preceding synchronous AppleScript calls.
4. A transient UI's event tap must stop on dismissal, take only its intended
   combinations, and not take input from a Space where its UI is absent.
5. Start the reload watcher before independent module loads. A load failure
   must remain recoverable on the next edit; it currently can still prevent
   later modules from loading.
6. Do not introduce Spaces-aware `hs.window.filter` queries. The removed
   Emojis refocus filter must stay removed on upstream updates.
7. Shell validators must report failures explicitly under `pipefail`, and
   cadence measurements must name maintained paths to exclude vendor data.
8. PR descriptions become squash commit messages. Review-cycle evidence
   belongs in PR comments; snapshots retain codebase-review evidence.

## Findings

### Open and Moved

#### Bug

- `expanse-chooser-gc` — **The expansion chooser has no durable reference when opened without a frontmost window.** Bug · Moved · Read.
  - Where: `expanse.lua:90` (`pick_expanse`).
  - Severity: P3 (downgraded from P2; earlier general scenario corrected).
  - Installed `hs/chooser.lua` retains `whichChooser` as a key in `_lastFocused` only when `hs.window.frontmostWindow()` supplies a value. With no visible window that value is nil, so the function-local is the only Lua reference; native chooser GC releases its completion callback. The installed default callback was exercised with stub dependencies to confirm the conditional rooting, but native GC/UI failure was not reproduced. Hold one chooser at module scope rather than relying on focus state.
  - Review backlog: `expanse-chooser-fixes`
- `expanse-truncate-utf8` — **Long chooser subtext can split a UTF-8 character.** Bug · Moved · Verified.
  - Where: `expanse.lua:77` (`get_expanses`, truncation through line 79).
  - Severity: P3.
  - Running the actual picker with stubbed `expanse dump` output `string.rep("ab↵", 40)` produced subtext whose `utf8.len` is nil at byte 48. Byte-based `sub` cuts the newline marker or any other multibyte text. Cut at UTF-8 boundaries instead; this reproduction establishes the invalid string, not its appearance in AppKit.
  - Review backlog: `expanse-chooser-fixes`
- `leader-tap-ignores-mouse` — **Two modifier-assisted clicks can activate the leader.** Bug · Open · Verified.
  - Where: `leader.lua:138` (`M.tap`).
  - Severity: P3.
  - Mouse and scroll events cannot cancel a pending tap because only `flagsChanged` and `keyDown` are observed. Feeding the actual tap callback two right-Shift click sequences within 0.5 seconds entered the root modal in a stub harness. Observe mouse-down and scroll events and reset pending tap state; macOS event delivery was not exercised.
  - Review backlog: `leader-stray-input`
- `overlay-escape-ignores-modifiers` — **Open overlays swallow modified Escape as well as plain Escape.** Bug · Open · Verified.
  - Where: `overlay.lua:31` (`escTap` callback).
  - Severity: P3.
  - The actual callback returns true and closes the overlay for a stub Cmd+Escape event, because it checks only keycode 53. A focused application's modified Escape shortcut therefore cannot receive that event while the tap is active. Check modifiers before consuming Escape; the callback was tested, not global OS routing.
  - Review backlog: `overlay-follow-spaces`
- `floatcalendar-keys-taken-off-space` — **A calendar left on another Space can keep taking arrows, R and Escape.** Bug · Open · Read.
  - Where: `Spoons/FloatCalendar.spoon/init.lua:120` (canvas construction), `:323` (`startKeys`).
  - Severity: P3.
  - No all-Spaces collection behaviour or Space-change dismissal is set, while the event tap remains global. Open the calendar and swipe to another Space without a key or click: the default one-Space window behaviour leaves the calendar behind but its keys active. The leader toggle may only dismiss it because `o` closes it and starts the toggle grace before `l`. Confirm with a Space swipe before selecting all-Spaces behaviour or dismissal.
  - Review backlog: `floatcalendar-follow-spaces`
- `overlay-keys-taken-off-space` — **An overlay left on another Space can keep swallowing Escape and make the next toggle show nothing.** Bug · Open · Read.
  - Where: `overlay.lua:17` (toggle), `:23` (webview creation), `:30` (tap).
  - Severity: P3.
  - The webview constructor leaves default collection behaviour while the Escape tap stays active. After a Space swipe, the next toggle deletes the retained webview instead of displaying one locally. Confirm in the app; then make the view follow Spaces or hide it when leaving its Space, without a Spaces-aware window filter.
  - Review backlog: `overlay-follow-spaces`
- `floatcalendar-pre-1900-error` — **Navigating below the supported date range raises errors and leaves the selected date invalid.** Bug · Open · Verified.
  - Where: `Spoons/FloatCalendar.spoon/init.lua:63` (previous month's date), `:251` (`prevYear`).
  - Severity: P3.
  - On local Lua 5.5.1, the actual `prevYear()` from January 1901 mutates the year to 1900 and then raises because `os.time{year=1900, month=1, day=0}` is unsupported. Repeated Up keeps moving deeper into the invalid range; `resetDate()` recovers. Bound navigation to supported dates or roll back state on a failed redraw. The embedded Lua 5.4 boundary was not executed.

#### Design

- `leader-unbound-key-stays-live` — **An unmatched key leaves the leader active and later typing can launch an app.** Design · Open · Verified.
  - Where: `leader.lua:139` (`keyDown` handling), `:51` (`activate`); current app tree at `init.lua:43`.
  - Severity: P3.
  - With the root modal open, the current-tree stub reproduction of `cat` passes `c`, enters Apps on `a`, and invokes Todoist on `t`. Resetting tap detection does not deactivate the modal. Track each modal's combinations and close it on an unmatched key before ordinary typing continues.
  - Review backlog: `leader-stray-input`
- `leader-alert-closeall` — **Opening or closing the leader removes unrelated alerts.** Design · Open · Verified.
  - Where: `leader.lua:43` (`deactivate`), `:50` (`activate`).
  - Severity: P3.
  - The actual leader code calls `hs.alert.closeAll()` when activating and timing out; a stub alert store confirmed removal of a pre-existing unrelated alert. Retain the leader's alert ID and close only that alert. No running-app observation.
- `aclock-escape-swallow` — **The clock takes plain Escape globally while shown.** Design · Open · Read.
  - Where: `init.lua:29`; `Spoons/AClock.spoon/init.lua:49` (default), `:124` (binding).
  - Severity: P3.
  - AClock binds Escape for its four-second display, taking it from Vim or dialogs. Disabling its dismiss hotkey in configuration avoids the effect without editing upstream code; whether that dismiss key is wanted remains a user decision.
- `init-loads-unprotected` — **One module's load error prevents later bindings from being initialized.** Design · Open · Read.
  - Where: `init.lua:11` through `:19`, before `leader.setup` at `:27` and capture hotkeys at `:52`.
  - Severity: P3.
  - Installed `_coresetup.lua` calls the spoon's `require` and `init` directly. A runtime error in any of these loads aborts initialization before the leader or capture keys bind. The early watcher preserves edit recovery but not partial functionality. Protect independent loads and omit unavailable actions while reporting errors; no current failing module was observed.

#### Performance

- `expanse-blocking-execute` — **Opening and selecting an expansion synchronously runs an external process.** Performance · Moved · Read.
  - Where: `expanse.lua:24` (`hs.execute`), called at `:54` and `:73`.
  - Severity: P3.
  - The Python CLI must exit before Hammerspoon handles more callbacks. A slow command delays other keys; no noticeable stall was measured. Use `hs.task` if this becomes a problem.
- `spotify-serial-applescript` — **A now-playing request makes five sequential synchronous AppleScript calls.** Performance · Moved · Read.
  - Where: `spotify.lua:52`, `:58`, `:59`, `:62`, and artwork query `:22`.
  - Severity: P3.
  - Track, artist, album, playing state and artwork URL are separate synchronous calls in the installed Spotify wrapper; `isRunning` is an application lookup, not another Apple Event. A hung Spotify can block before the three-second image timer starts. Combine the fields and consider asynchronous `osascript`; no timeout stall was reproduced.
